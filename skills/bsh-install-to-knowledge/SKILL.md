# BSH-Install to Knowledge (v1.0)

将 BSH 产品安装操作指南（PPT/PPTX/PDF 幻灯片）转换为**多文件知识手册体系**，供大模型逐步执行安装引导。

---

## 适用场景

- BSH 家电产品售后客服安装引导（洗衣机、烘干机、冰箱、烤箱、洗碗机、油烟机、灶具等）
- PPT/PDF 形式沉淀的安装流程文档（每页一个或多个产品安装决策树）
- 需要将"安装流程图"转化为"LLM 可逐步执行的安装引导指令集"的场景

---

## 核心设计原则

1. **一棵安装树 = 一个独立 MD 文件** — 减少上下文噪声，独立维护
2. **文件内嵌 Mermaid 导航锚** — 分支验证，防止走错路径
3. **越界退出协议每文件独立定义** — 不同产品的安装边界不同
4. **全局索引文件提供产品分流入口** — 根据用户产品类型定位正确文件

---

## 命名规范

### 产品系列代码

推导规则：从产品中文名提取英文关键词，取 2–4 个大写字母。首次确定时向用户确认。

| 产品中文名 | 产品系列代码 | 推导依据 |
|-----------|-------------|---------|
| 洗衣机 | `WM` | Washing Machine |
| 壁挂式洗衣机 | `WWM` | Wall Washing Machine |
| 烘干机 | `DRY` | Dryer |
| 冰箱 | `REF` | Refrigerator |
| 洗碗机 | `DW` | Dishwasher |
| 油烟机 | `HOOD` | Range Hood |
| 灶具 | `HOB` | Hob/Cooktop |
| 烤箱/蒸箱 | `OVEN` | Oven/Steamer |
| 微波炉 | `MW` | Microwave |
| 咖啡机 | `CF` | Coffee |
| 电热水器 | `WH` | Water Heater |
| 暖碟抽屉 | `WD` | Warming Drawer |
| 消毒柜 | `DSF` | Disinfector |
| 酒柜 | `WC` | Wine Cooler |
| 净饮机 | `WP` | Water Purifier |

> 当多个产品合在同一份指南中时，系列代码使用 `INST`（Installation），文件名中用子编号区分产品。

### 索引文件

```
BSH_INST_{版本号}_index.md
```

### 独立安装树文件

```
BSH_INST_I{nn}_{产品关键词}.md
```

| 字段 | 规则 |
|------|------|
| `I{nn}` | 两位数安装编号，从 `01` 起，按页面顺序递增 |
| `产品关键词` | 中文，2–6 字，取安装树标题核心词 |

**示例**：`BSH_INST_I01_洗衣机.md`、`BSH_INST_I02_壁挂洗衣机.md`、`BSH_INST_I05_洗碗机.md`

## 执行约定标记

| 标记 | 含义 | 说明 |
|------|------|------|
| `【话术】` | 逐字朗读给用户的引导话术 | 原文不改 |
| `【判断】` | 条件分支 | 根据用户回答触发 |
| `【派工】` | 安排工程师上门 | 含申请备注 |
| `【备注模板】` | 派工申请备注的可复制文本 | 客服必须带入系统 |
| `【材料确认】` | 确认用户是否需要工程师带材料 | 水龙头、连接件等 |
| `【发短信】` | 调用阿里云短信接口发送短信 | 格式：`品牌 → SMS_CODE`，LLM 根据用户品牌选择对应 code 调用 |
| `【提醒】` | 内部提醒（不对用户播报） | 价格政策、特殊规则等 |
| `【解释】` | 向用户解释原理/现象 | 安抚或科普 |
| `【操作指导】` | 指导用户自行操作或准备 | 如联系橱柜公司 |
| `【引用】` | 跨安装树引用 | `→ 参见 BSH_INST_I{nn}_{产品}.md` |
| `▶` | 无条件进入下一步 | |
| `[节点]` | 对应 Mermaid 节点 ID | 导航自验 |

## 文档结构

### 索引文件结构

```markdown
# BSH 各产品组安装操作指南索引 {版本号}

## 一、使用说明
## 二、文件清单
  | 编号 | 文件名 | 产品类型 | PPT来源页 |
## 三、一级分流表
  | 用户产品关键词 | 分流到文件 | 备注 |
## 四、跨安装树引用关系
## 五、版本与适用范围
```

### 独立安装树文件结构（五节 + 两附录）

```markdown
# BSH {产品} 安装引导手册

## 一、文档使用说明
  - 执行铁律 + 标记表

## 二、安装引导导航树
  - Mermaid 源码（flowchart TD）
  - 步骤 ↔ 节点速查表

## 三、越界处理协议

## 四、引导入口
  - 产品确认 / 安装类型确认

## 五、引导步骤详情
  - I01 … I{nn}（含子步骤 I{nn}A/B/C）

附录 A：申请备注模板汇总
附录 B：材料费用与短信口径汇总
```

## 转换步骤

### Step 0 — 预处理

#### 0-1：确定提取路径

| 输入形式 | 路径 |
|---------|------|
| PPTX/PDF 可读取文本 | 结构路径：逐页提取 |
| 仅有截图 | 视觉路径：图片识别 |

#### 0-2：过滤非流程页

跳过：封面、版本记录、致谢、纯图例页。记录页码。

#### 0-3：安装树边界识别

每页标题 = 一个产品安装类型。判断规则：
- 标题相同/为子标题 → 合并
- 标题不同 → 独立安装树
- "返回首页产品组选择" → 跨树引用，不合并
- **跨页归属不明确时必须向用户确认**

输出：**安装树清单**（名称、来源页码、是否合并）

#### 0-4：按安装树提取节点与边

| 提取对象 | 表现形式 | 提取为 |
|---------|---------|--------|
| 引导问题 | "请问"、"？" | 【判断】 |
| 用户回答分支 | 箭头标签/短文本 | 条件分支 |
| 客服话术 | 长段落（≥20字） | 【话术】/【解释】 |
| 操作建议 | 含操作动词 | 【操作指导】 |
| 派工出口 | "派工"、"安排工程师上门" | 【派工】 |
| 用户接受出口 | "用户接受"、"生成信息咨询" | 结束节点 |
| 申请备注 | "!!!!注意"块 / "申请备注（可复制）" | 【备注模板】 |
| 材料确认 | 水龙头/连接件/波纹管价格 | 【材料确认】 |
| 发短信指令 | "搜XX"、"发短信操作" | 【发短信】 |
| 内部提醒 | "提醒："、"备注：" | 【提醒】 |
| 跨树引用 | "返回首页产品组选择" | 【引用】 |

---

### Step 1 — 生成索引文件

1. 文件清单表：按 I{nn} 列出所有安装树
2. 一级分流表：按产品名称/类型映射到文件（每个安装树至少 3 个关键词）
3. 跨树引用关系
4. 版本信息

---

### Step 2 — 划分引导步骤

编号 `I{nn}`，边界原则：
1. 每个向用户提问开启新 I 步骤
2. 同一问题多分支用 `I{nn}A` / `I{nn}B` / `I{nn}C`
3. 派工/用户接受不单独编号，作为所属步骤的结束动作
4. 单树步骤通常不超过 10 步

---

### Step 3 — 提取话术

| 类型 | 识别特征 | 处理 |
|------|---------|------|
| 引导话术 | "请问"开头 | `【话术】` 原文不改 |
| 解释话术 | 向用户解释 | `【解释】` 原文不改 |
| 操作引导 | 含步骤/操作动词 | `【操作指导】` 原文不改 |

**禁止改写话术**，缺失用 `（话术待补充）` 占位。

---

### Step 4 — 提取判断逻辑

判断表固定四列：

```markdown
| 条件 | 下一步 | 出口类型 | Mermaid 边验证 |
|------|--------|---------|--------------|
| {用户回答} | → **I{xx}** | 继续引导 | `SRC --标签--> TGT` ✓ |
| 用户接受 | → 结束 | 接受/信息咨询 | ... |
| 坚持要求上门 | → 派工 | 派工 | ... |
| 其他 | →【越界退出】| 越界 | 无对应边 |
```

每张表必须有兜底越界行。

---

### Step 5 — 提取派工信息与申请备注

安装场景的核心产出是**申请备注模板**：

| 字段 | 说明 |
|------|------|
| 触发条件 | 导致派工的路径摘要 |
| 备注模板文本 | 客服复制到系统的原文 |
| 材料备注 | 是否带材料、哪种规格 |

汇总至附录 A。

---

### Step 6 — 提取材料确认与发短信

| 字段 | 说明 |
|------|------|
| 材料名称 | 水龙头/连接件/波纹管/支架等 |
| 规格/价格 | 如"79/150/205 元三种水龙头" |
| 发短信 | 调用阿里云短信接口，按品牌选择 SMS code |

**【发短信】格式规范**：

原始 PDF 中的表述（如"西门子搜49；博世搜50"）是人工客服在系统中搜索的口径编号。转换时需改写为阿里云短信接口调用格式：

```markdown
【发短信】
| 品牌 | SMS_CODE | 短信内容摘要 |
|------|----------|-------------|
| 西门子 | {code_siemens} | {内容描述} |
| 博世 | {code_bosch} | {内容描述} |
```

- `SMS_CODE` 即原始的口径编号（如 "49"、"339"）
- LLM 执行时根据用户品牌选择对应 code，调用短信接口
- 若原始 PDF 仅标注了一个品牌的编号，另一品牌标注"（待补充）"

汇总至附录 B。

---

### Step 7 — 提取跨树引用

"返回首页产品组选择" → `【引用】→ 参见索引文件重新分流`

产品内部跨页引用（如壁挂洗衣机引用洗衣机的水龙头流程）也需标注。

---

### Step 8 — 定义越界处理协议

触发条件（至少覆盖）：
1. 用户产品无法匹配当前安装树
2. 用户回答无法映射到任何条件行
3. 用户询问非安装类问题（维修、退换、价格政策等）
4. 用户情绪激烈/要求投诉
5. 用户描述属于其他产品的安装流程

退出动作：
1. 属于其他产品 → 引用跳转
2. 无法定位 → 转人工
3. 用户要求 → 转人工

---

### Step 9 — 生成 Mermaid 安装树

规范：
- `flowchart TD`
- 引导问题 → 菱形 `{...}`
- 话术/解释 → 矩形 `[...]`
- 派工出口 → 圆角矩形 `([...])`
- 用户接受 → 圆角矩形 `([...])`
- 跨树引用 → 双圆角 `((...))` 
- 节点 ID：`{产品缩写}_{序号}`，如 `WM_01`

---

### Step 10 — 生成步骤 ↔ 节点速查表

```markdown
| 引导步骤 | Mermaid 节点 | 步骤类型 | 预期下一节点 |
|---------|-------------|---------|------------|
| I01 | `WM_01` | 判断 | `WM_02` / `WM_03` |
```

---

### Step 11 — 生成 ASCII 路径图

```
I01 产品确认/安装环境确认
 ├─ 条件A → I02 材料确认
 │   ├─ 用户自备 → 【派工】备注：XXX
 │   ├─ 工程师带 → 【派工】备注：YYY
 │   └─ 不确定 → 【派工】备注：ZZZ
 ├─ 条件B → I03 建议暂缓
 │   ├─ 用户接受 → 生成信息咨询
 │   └─ 坚持上门 → 【派工】
 └─ 其他 → 【越界退出】
```

## 质量检查清单

### 索引文件
- [ ] 文件清单覆盖所有安装树，编号连续
- [ ] 分流表每棵树至少 3 个关键词
- [ ] 跨树引用双向完整

### 独立安装树文件
- [ ] 五节 + 两附录结构完整
- [ ] Mermaid 内嵌且结构正确
- [ ] 每个判断表有兜底越界行
- [ ] 越界协议独立成节
- [ ] 话术原文未被改写
- [ ] 所有"申请备注（可复制）"均已提取至附录 A
- [ ] 材料规格/价格/发短信口径均已提取至附录 B
- [ ] `【提醒】` 标记的内部信息未混入对用户话术中

---

## 执行顺序

```
Step 0: 预处理（路径 → 过滤 → 边界识别 → 提取节点）
Step 1: 生成索引文件
Step 2–8: 对每棵安装树执行（划分步骤 → 话术 → 判断 → 派工备注 → 材料短信 → 跨树引用 → 越界协议）
Step 9: Mermaid
Step 10: 速查表
Step 11: ASCII 路径图
最终: 质量检查
```
