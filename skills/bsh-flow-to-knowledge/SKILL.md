# BSH-Flow to Knowledge (v1.0)

将 BSH 产品故障树（PPT/PPTX 流程图）转换为**多文件故障诊断知识手册体系**，供大模型按用户故障描述分诊后逐步执行排障。

---

## 适用场景

- BSH 家电产品售后客服维修排障（冰箱、洗衣机、洗碗机、油烟机、灶具、烤箱、咖啡机、电热水器、消毒柜、暖碟抽屉等）
- PPT/PPTX 形式沉淀的故障诊断决策树（每页或多页一棵故障树）
- 需要把"故障流程图"转化为"LLM 可逐步执行的排障引导指令集"的场景

---

## 核心设计原则

1. **一棵故障树 = 一个独立 MD 文件** — 减少上下文噪声，独立维护，单次召回精确
2. **文件内嵌 Mermaid 导航锚** — 节点 ID 自验，防止走错分支
3. **越界退出协议每文件独立定义** — 不同故障类型的边界不同
4. **产品级索引文件提供故障分流入口** — 根据用户故障描述定位正确文件

---

## 命名规范

### 产品系列代码

推导规则：从产品中文名 / PPT 标题提取英文关键词，取 2–4 个大写字母。同一产品多份来源 PPT 用尾号区分（如 `DW`、`DW2`）。首次确定时向用户确认。

### 索引文件

```
BSH_<CODE>_V<版本>_index.md
```

每份来源 PPT 一个索引文件。同一产品下有 `<CODE>` 与 `<CODE2>` 时，两份索引共存于同一产品目录，再补一个产品级 `_index.md` 做聚合入口。

### 独立故障树文件

```
BSH_<CODE>_F<nn>_<故障关键词>.md
```

| 字段 | 规则 |
|------|------|
| `F<nn>` | 两位数故障编号，从 `01` 起，按 PPT 页面顺序递增 |
| `<故障关键词>` | 中文，2–6 字，取故障树标题核心词（如 `不通电`、`异常显示`、`漏水`） |

**示例**：`BSH_DW_F01_不通电.md`、`BSH_REF_F02_不制冷.md`、`BSH_HOB_F04_报警.md`

## 执行约定标记

| 标记 | 含义 | 说明 |
|------|------|------|
| `【话术】` | 逐字朗读给用户的引导话术 | 原文不改 |
| `【判断】` | 条件分支（"请问…？"） | 根据用户回答触发 |
| `【派工】` | 安排工程师上门 | 含申请备注 |
| `【备注模板】` | 派工申请备注的可复制文本 | 客服必须带入系统 |
| `【发短信】` | 调用短信接口发送排障短信 | 格式：`品牌 → SMS_CODE` |
| `【提醒】` | 内部提醒（不对用户播报） | 价格政策、特殊规则等 |
| `【解释】` | 向用户解释原理/现象 | 安抚或科普 |
| `【操作指导】` | 指导用户自行操作排查 | 拔插电源、检查门封等 |
| `【故障代码】` | 系统显示的错误代码 | 如 `E1000`、`A2310` |
| `【引用】` | 跨故障树引用 | `→ 参见 BSH_<CODE>_F<nn>_<故障>.md` |
| `▶` | 无条件进入下一步 | |
| `[节点]` | 对应 Mermaid 节点 ID | 导航自验 |

## 文档结构

### 索引文件结构

```markdown
# BSH <产品> 故障诊断索引 V<版本>

## 一、使用说明
  - 一级分诊入口
  - 文件体系
  - 分流执行方法
  - 三条执行铁律（不越界 / 不编造 / 不跳步）

## 二、文件清单
  | 编号 | 文件名 | 故障类型 | Mermaid 节点前缀 | PPT 来源页 |

## 三、一级分流表
  | 用户描述关键词 | 分流到文件 | 备注 |

## 四、跨故障树引用关系
  | 来源文件 | 引用目标文件 | 触发条件 |

## 五、产品系列与适用机型
```

### 独立故障树文件结构（五节 + 两附录）

```markdown
# BSH <产品> <故障类型> 诊断手册

## 一、文档使用说明
  - 三条执行铁律 + 标记表

## 二、诊断决策树
  - Mermaid 源码（flowchart TD）
  - 步骤 ↔ 节点速查表

## 三、越界处理协议

## 四、诊断入口
  - 故障现象确认 / 故障代码确认

## 五、诊断步骤详情
  - D01 … D<nn>（含子分支 D<nn>A/B/C）

附录 A：申请备注模板汇总
附录 B：故障代码与发短信口径汇总
```

> 故障树用 `D<nn>`（Diagnosis）编号，与安装树的 `I<nn>`（Installation）区分。

## 转换步骤

### Step 0 — 预处理

#### 0-1：确定提取路径

| 输入形式 | 路径 |
|---|---|
| PPTX 可读文本 | 结构路径：逐页解析 shape/text |
| 仅有截图 | 视觉路径：图片识别（参考 image-to-knowledge skill） |

#### 0-2：过滤非流程页

跳过：封面、目录、版本记录、致谢、纯图例页。**记录被过滤页号写入索引底部"被过滤的非流程页"区**。

#### 0-3：故障树边界识别

每页标题 = 一棵故障树。判断规则：
- 标题相同/为子标题 → 合并
- 标题不同 → 独立故障树
- "返回首页故障组选择" / "返回主菜单" → 跨树引用，不合并
- 故障代码（如 `E1000`、`A2310`）出现在标题位置 → 独立故障树
- **跨页归属不明确时必须向用户确认**

输出：**故障树清单**（名称、来源页码、是否合并、推断 CODE）

#### 0-4：按故障树提取节点与边

| 提取对象 | 表现形式 | 提取为 |
|---|---|---|
| 引导问题 | "请问…？"、菱形 | 【判断】 |
| 用户回答分支 | 箭头标签 | 条件分支 |
| 客服话术 | 长段落（≥20 字）、矩形 | 【话术】/【解释】 |
| 操作建议 | 含操作动词 | 【操作指导】 |
| 派工出口 | "派工"、"安排工程师" | 【派工】 |
| 用户接受出口 | "用户接受"、"生成信息咨询" | 结束节点 |
| 申请备注 | "申请备注（可复制）"块 | 【备注模板】 |
| 故障代码 | `E\d+`、`A\d+`、`F\d+` 等 | 【故障代码】 |
| 发短信 | "搜 XX"、"发短信" | 【发短信】 |
| 内部提醒 | "提醒："、"注意：" | 【提醒】 |
| 跨树引用 | "返回首页…"、"参见…" | 【引用】 |

---

### Step 1 — 生成索引文件

1. **文件清单表**：按 F<nn> 列出所有故障树
2. **一级分流表**：从故障树标题、首个判断问题、故障代码自动抽取关键词，每棵树 ≥ 3 个关键词；标注"自动抽取关键词，待人工扩充同义词"
3. **跨故障树引用关系**：双向完整
4. **产品系列与适用机型**：CODE、来源 PPT、版本、生成日期、转换状态

---

### Step 2 — 划分诊断步骤

编号 `D<nn>`，边界原则：
1. 每个向用户提问开启新 D 步骤
2. 同一问题多分支用 `D<nn>A` / `D<nn>B` / `D<nn>C`
3. 派工/用户接受/转人工 不单独编号，作为所属步骤的结束动作
4. 单树步骤通常不超过 12 步

---

### Step 3 — 提取话术

| 类型 | 识别特征 | 处理 |
|---|---|---|
| 引导话术 | "请问"开头 | `【话术】` 原文不改 |
| 解释话术 | 向用户解释现象 | `【解释】` 原文不改 |
| 操作引导 | 含操作动词（拔插、按住、查看） | `【操作指导】` 原文不改 |

**禁止改写话术**，缺失用 `（话术待补充）` 占位。

---

### Step 4 — 提取判断逻辑

判断表固定四列：

```markdown
| 条件 | 下一步 | 出口类型 | Mermaid 边验证 |
|---|---|---|---|
| {用户回答} | → **D<xx>** | 继续诊断 | `SRC --标签--> TGT` ✓ |
| 用户接受 | → 结束 | 接受/信息咨询 | ... |
| 坚持上门 | → 派工 | 派工 | ... |
| 故障代码 E1000 | → **D<xx>** | 代码分诊 | ... |
| 其他 | →【越界退出】 | 越界 | 无对应边 |
```

每张表必须有兜底越界行。

---

### Step 5 — 提取派工信息与申请备注

故障场景的核心产出之一是**申请备注模板**：

| 字段 | 说明 |
|---|---|
| 触发条件 | 导致派工的诊断路径摘要 |
| 备注模板文本 | 客服复制到系统的原文 |
| 故障代码备注 | 触发派工的代码（如有） |

汇总至附录 A。

---

### Step 6 — 提取故障代码与发短信

| 字段 | 说明 |
|---|---|
| 故障代码 | `E1000`、`A2310`、`F0000` 等 |
| 含义/分诊路径 | 该代码触发哪条诊断路径 |
| 发短信 | 按品牌选择 SMS code 调用接口 |

**【发短信】格式规范**：

```markdown
【发短信】
| 品牌 | SMS_CODE | 短信内容摘要 |
|------|----------|-------------|
| 西门子 | {code_siemens} | {内容描述} |
| 博世 | {code_bosch} | {内容描述} |
```

汇总至附录 B。

---

### Step 7 — 提取跨故障树引用

- "返回首页故障组选择" → `【引用】→ 参见 _index.md 重新分流`
- 同产品内跨故障树引用（如"洗不干净"引用"水垢残留"流程） → 标注双向关系
- 跨产品引用（如"嵌饮机参考咖啡机除垢"） → `【引用】→ 参见 BSH_<其他产品CODE>_F<nn>_*.md`

---

### Step 8 — 定义越界处理协议

触发条件（至少覆盖）：
1. 用户故障描述无法匹配当前故障树
2. 用户回答无法映射到任何条件行
3. 用户询问非排障类问题（安装、价格、退换等）
4. 用户情绪激烈/要求投诉
5. 用户描述属于其他产品的故障

退出动作：
1. 属于其他故障树 → 索引重分流
2. 属于其他产品 → 跨产品引用
3. 无法定位 → 转人工
4. 用户要求 → 转人工

---

### Step 9 — 生成 Mermaid 决策树

规范：
- `flowchart TD`
- 引导问题 → 菱形 `{...}`
- 话术/解释 → 矩形 `[...]`
- 派工出口 → 圆角矩形 `([...])`
- 用户接受 → 圆角矩形 `([...])`
- 跨树引用 → 双圆角 `((...))`
- 节点 ID：`<故障前缀>_<序号>`，如 `NP_01`（不通电）、`DA_01`（异常显示）。**故障前缀写入索引"文件清单"列**。

---

### Step 10 — 生成步骤 ↔ 节点速查表

```markdown
| 诊断步骤 | Mermaid 节点 | 步骤类型 | 预期下一节点 |
|---|---|---|---|
| D01 | `NP_01` | 判断 | `NP_02` / `NP_03` |
```

## 质量检查清单

### 索引文件
- [ ] 文件清单覆盖所有故障树，编号连续
- [ ] 分流表每棵树至少 3 个关键词
- [ ] 故障代码已纳入分流关键词
- [ ] 跨树引用双向完整
- [ ] 被过滤页码已记录

### 独立故障树文件
- [ ] 五节 + 两附录结构完整
- [ ] Mermaid 内嵌且节点 ID 与速查表一致
- [ ] 每个判断表有兜底越界行
- [ ] 越界协议独立成节
- [ ] 话术原文未被改写
- [ ] 所有"申请备注（可复制）"已提取至附录 A
- [ ] 所有故障代码与发短信口径已提取至附录 B
- [ ] `【提醒】` 标记的内部信息未混入对用户话术

## 批处理工具

仓库内 `tools/bsh_flow_to_knowledge_batch.py` 可批量处理 PPTX → 多文件 MD：

```bash
python3 tools/bsh_flow_to_knowledge_batch.py \
    --input-dir <PPT 目录> \
    --output-dir <扁平输出目录> \
    --report-path <批处理报告>.md
```

**注意**：批处理脚本输出是**自动草案**，必须按本 Skill 的"质量检查清单"复核后再入库到 `fault-diagnosis/<CODE_中文名>/`。

---

## 入库流程

1. 用本 Skill / 批处理工具产出扁平输出
2. 按 CODE 移入 `fault-diagnosis/<CODE_中文名>/`，索引文件命名为 `BSH_<CODE>_V<版本>_index.md`
3. 同产品多来源时补一个产品级 `_index.md` 做聚合入口
4. 更新 `manifests/volcengine/fault-diagnosis.jsonl`
5. 用 `tools/volcengine_kb_import.py` 上传到火山引擎 KB
