# Skill: BSH-Flow to Knowledge (v1.0)

将 BSH 产品故障诊断树（PPT/PPTX 幻灯片）转换为**多文件知识手册体系**，供大模型逐步执行故障诊断。

---

## 适用场景

- BSH 家电产品售后客服故障诊断（冰箱、洗衣机、烤箱等）
- PPT 形式沉淀的故障树文档（每页一棵或多棵诊断子树）
- 需要将"故障树意图"转化为"LLM 可逐步执行的诊断指令集"的场景

---

## 与通用 Skill 的核心差异

| 维度 | 通用 Flowchart to Knowledge | BSH-Flow to Knowledge（本文档） |
|------|---------------------------|-------------------------------|
| 输入结构 | 线性 IVR 流程图 | 树形故障诊断图（多分支、多出口） |
| 产出形式 | 单一知识手册文件 | **多文件体系**：每棵故障树独立 MD + 全局索引 |
| 阶段编号 | S01–S{nn}（线性序列） | D{nn}（诊断步骤，树形展开） |
| 特有标记 | 【播报】【判断】【写入】【跳转】 | 新增【诊断码】【派工】【配件】【视频】【话术】【引用】 |
| 跳转机制 | 流程内阶段跳转 | **跨文件引用**（故障树 A → 故障树 B） |
| 出口类型 | 人工转接、流程终止 | 派工、用户接受（ACC）、跨树引用、人工转接 |

---

## 核心设计原则

### 原则 1：一棵故障树 = 一个独立 MD 文件

每棵故障树（通常对应 PPT 一页或相邻几页的同主题内容）输出为一个独立 MD 文件。理由：
- 诊断场景下，LLM 只需加载当前故障树，减少上下文噪声
- 不同故障树可独立维护、版本管理
- 跨树引用通过标准化文件名实现

### 原则 2：诊断树内嵌 Mermaid 导航锚

每个独立 MD 文件**必须内嵌**该故障树的完整 Mermaid 源码。理由：
- 故障树分支密集，LLM 需要可验证的边列表防止走错分支
- 每个诊断步骤标注 `[节点：XXX → YYY]`，跳转前可对照图自验

### 原则 3：越界退出协议，每文件独立定义

每个故障树 MD 文件必须包含独立的越界处理协议。不同故障树的越界边界不同，不可共用。

### 原则 4：全局索引文件提供分流入口

索引文件是 LLM 的**一级分诊入口**——根据用户描述的故障现象，定位到正确的故障树文件。

## 命名规范

### 产品系列代码

产品系列代码是贯穿索引文件和故障树文件的公共前缀，推导规则：

1. 优先取 BSH 内部已有的产品线英文缩写（如有）
2. 若无内部缩写，从产品中文名提取英文关键词，取 2–4 个大写字母
3. 同一批次处理的所有文件必须使用相同的产品系列代码
4. **首次确定时向用户确认**，后续文件沿用

| 推导示例 | 产品中文名 | 产品系列代码 | 推导依据 |
|---------|-----------|-------------|---------|
| 冰箱类 | 对开门冰箱 | `SBS` | Side-by-Side |
| 冰箱类 | 三门冰箱 | `TD` | Three-Door |
| 洗涤类 | 滚筒洗衣机 | `FLW` | Front-Load Washer |
| 洗涤类 | 洗碗机 | `DW` | Dishwasher |
| 烹饪类 | 嵌入式烤箱 | `OVEN` | Oven |
| 烹饪类 | 蒸箱 | `STM` | Steamer |

### 索引文件（标准命名）

```
BSH_{产品系列}_{版本号}_index.md
```

| 字段 | 规则 |
|------|------|
| `产品系列` | 见上方推导规则 |
| `版本号` | 与原始 PPT 版本号一致，格式 `V{X.Y}` |

**示例**：`BSH_SBS_V1.0_index.md`、`BSH_FLW_V2.1_index.md`

### 独立故障树文件（故障编号命名）

```
BSH_{产品系列}_F{nn}_{故障关键词}.md
```

| 字段 | 规则 |
|------|------|
| `产品系列` | 同索引文件 |
| `F{nn}` | 两位数故障编号，从 `01` 开始，按 PPT 页面顺序递增 |
| `故障关键词` | 中文，2–6 字，取故障树标题核心词（去掉"问题"等泛化后缀） |

**编号分配规则**：
1. 按 PPT 中故障树出现的页面顺序，依次分配 F01、F02、F03...
2. **相邻页面属于同一故障树的，合并为同一编号**（如 PPT 第 16、17 页都是冷凝水相关 → 合并为一个 F 编号）
3. 合并时在索引文件中标注来源页码范围
4. 编号一旦分配不可复用，即使后续删除某棵树，编号留空不回收

**故障关键词提取规则**：
1. 直接取 PPT 页面标题的核心名词短语
2. 去掉"问题"、"故障"等泛化后缀（如"噪音问题" → `噪音`）
3. 保留区分度（如"不出冰块"和"不出冰水"不可合并为"冰"）
4. 不超过 6 个中文字符

**示例**（以对开门冰箱为例）：

| 文件名 | 故障关键词来源 |
|--------|-------------|
| `BSH_SBS_F01_不通电.md` | PPT 标题"不通电（不制冷）" → 核心词"不通电" |
| `BSH_SBS_F02_不制冷.md` | PPT 标题"不制冷（通电）" → 核心词"不制冷" |
| `BSH_SBS_F05_噪音.md` | PPT 标题"噪音问题" → 去后缀"噪音" |

> 以上仅为推导示例，实际编号和关键词在执行时按 Step 0-3 的故障树清单确定。

## 文档结构

### 索引文件结构

```
# BSH {产品中文名} 故障诊断索引 {版本号}

## 一、使用说明
  - 本索引用途
  - 文件体系说明
  - 分流执行方法

## 二、文件清单
  | 编号 | 文件名 | 故障类型 | 诊断码范围 | PPT 来源页 |

## 三、一级分流表
  | 用户描述关键词 | 分流到文件 | 备注 |

## 四、跨故障树引用关系
  | 来源文件 | 引用目标文件 | 触发条件 |

## 五、产品系列与适用机型
  - 产品系列代码
  - 适用机型范围
  - 版本历史
```

### 独立故障树文件结构（固定五节 + 三附录）

```
# BSH {产品} — {故障名称} 诊断手册

## 一、文档使用说明
  - 三条执行铁律
  - 执行约定标记表

## 二、故障诊断导航树
  - 完整 Mermaid 源码（树形图，不裁剪）
  - 诊断步骤 ↔ 节点速查表

## 三、越界处理协议
  - 触发条件表
  - 退出动作
  - 严禁行为列表
  - 本文档覆盖范围（含跨树引用出口）

## 四、诊断入口
  - 故障主诉确认
  - 入口分支判断（如故障细分类型）

## 五、诊断步骤详情
  - D01 … D{nn}（含子步骤 D{nn}A/B/C）

附录 A：诊断码汇总表
附录 B：配件建议汇总表
附录 C：跨故障树引用清单
```

## 执行约定标记

| 标记 | 含义 | 说明 |
|------|------|------|
| `【话术】` | 逐字朗读给用户的诊断引导话术 | 原始 PPT 中客服话术原文 |
| `【判断】` | 根据用户回答或系统数据触发的条件分支 | 诊断树分支节点 |
| `【诊断码】` | BSH 标准诊断码 | 格式如 `111100000000`，附英文描述 |
| `【派工】` | 安排工程师上门 | 标注是否需要配件、是否需要视频 |
| `【配件】` | 预判所需配件 | 写入派工单，供工程师备件 |
| `【视频】` | 视频辅助标记 | `视频已有` / `视频：无需` / `视频待补充` |
| `【引用】` | 跨故障树引用跳转 | 格式：`→ 参见 BSH_{系列}_F{nn}_{故障名}.md` |
| `【解释】` | 向用户解释原理/现象的话术 | 非诊断性话术，用于安抚或科普 |
| `【操作指导】` | 指导用户自行操作的步骤 | 如重启、清洁封条、疏通排水孔等 |
| `▶` | 无条件进入下一诊断步骤 | |
| `[节点]` | 本步骤对应的 Mermaid 节点 ID | 用于导航自验 |

## 转换步骤

### Step 0 — PPT 预处理

#### Step 0-1：确定提取路径

| 输入形式 | 推荐路径 |
|---------|---------|
| PPTX 文件可被工具读取文本内容 | **结构路径**：逐页读取形状文字 + 连接线关系 + 备注 |
| 只有幻灯片截图 / 无法读取文件 | **视觉路径**：每张幻灯片作为独立图片处理 |

#### Step 0-2:过滤非流程页

以下幻灯片不参与故障树提取，记录页码后跳过：

| 页面特征 | 判断依据 |
|---------|---------|
| 封面 / 标题页 | 仅含产品名称、版本号、作者，无诊断内容 |
| 版本记录页 | 变更历史，无诊断逻辑 |
| 致谢 / 结尾页 | "Thanks" 等结尾性内容 |
| 纯图例说明页 | 仅说明颜色/符号语义，无诊断逻辑 |

记录被过滤页码，纳入索引文件备注。有效信息（如颜色语义）仍需提取。

#### Step 0-3：故障树边界识别

BSH 故障树 PPT 的典型结构：**每页标题 = 一个一级故障类型**。

1. 读取每页标题（PPT 标题形状或首行大字），作为故障树名称
2. 判断相邻页面是否属于同一故障树：
   - 标题相同或为子标题 → 合并
   - 标题完全不同 → 独立故障树
   - 页内有"跳转 {其他故障名}"指示 → 标记为跨树引用，**不**合并
3. **若跨页归属不明确，必须暂停并向用户确认，不得自行假设**
4. 输出：**故障树清单**（每棵树的名称、来源页码、是否需要合并）

#### Step 0-4：按故障树提取节点与边

对每棵故障树，分别提取：

| 提取对象 | PPT 中的表现形式 | 提取规则 |
|---------|----------------|---------|
| 诊断问题节点 | 包含"请问"、"？"的文本框 | 提取为【判断】入口 |
| 用户回答分支 | 箭头上的标签文字，或紧邻的短文本 | 提取为条件分支 |
| 话术/解释节点 | 长段落文本框（通常 ≥ 20 字） | 提取为【话术】或【解释】 |
| 操作指导节点 | 含步骤编号或操作动词的文本 | 提取为【操作指导】 |
| 派工出口 | "派工"、"我为您安排工程师上门" | 提取为【派工】 |
| ACC 出口 | "ACC"、"用户接受" | 提取为用户接受结束节点 |
| 诊断码节点 | 12 位数字码 + 英文描述 | 提取为【诊断码】 |
| 配件节点 | "需要配件"、具体配件名称 | 提取为【配件】 |
| 视频标记 | "视频已有"、"视频：无需" | 提取为【视频】 |
| 跨树引用 | "跳转 {故障名}" | 提取为【引用】 |
| DC 创建指令 | "创建...DC"、"新建...DC" | 提取为诊断码创建备注 |

### Step 1 — 生成索引文件

在提取完所有故障树后，**首先**生成索引文件：

1. **文件清单表**：按 F{nn} 编号列出所有故障树，标注文件名、故障类型、诊断码范围、来源页码
2. **一级分流表**：从 PPT 中提取用户可能的故障描述关键词，映射到对应故障树文件
3. **跨树引用关系**：汇总所有跨树引用，形成引用关系表
4. **产品信息**：提取封面页的产品名称、版本号、适用范围

#### 一级分流表构建规则

分流表是 LLM 的入口决策依据。构建方法：

| 来源 | 提取方式 |
|------|---------|
| PPT 故障树标题 | 直接作为一级关键词 |
| 诊断入口的第一个问题 | 提取问题中的名词短语作为关键词 |
| 诊断码英文描述 | 提取关键英文词，翻译为中文同义词 |
| 用户常见表述 | 基于话术中的用户回答，推断常见描述方式 |

每个故障树至少 3 个分流关键词，确保覆盖用户各种表述方式。

---

### Step 2 — 为每棵故障树划分诊断步骤

诊断步骤编号为 `D{nn}`，边界原则：

1. **每个诊断问题（向用户提问）开启一个新的 D 步骤**
2. 同一问题的多个回答分支，用子步骤 `D{nn}A`、`D{nn}B`、`D{nn}C` 区分
3. 回答分支内的后续诊断问题，编号递增（D01 → D02 → D03...）
4. **派工出口**和 **ACC 出口**不单独编步骤号，作为所属 D 步骤的结束动作
5. 跨树引用在当前步骤标注 `【引用】`，不展开引用目标内容

#### 步骤深度限制

单棵故障树的诊断步骤通常不超过 15 步。若超过，检查是否应拆分为多棵树。

---

### Step 3 — 提取话术与解释

从 PPT 文本框中提取：

| 类型 | 识别特征 | 处理方式 |
|------|---------|---------|
| 诊断引导话术 | 以"请问"开头，含"？" | 用 `【话术】` 包裹，原文不改 |
| 解释性话术 | 向用户解释原理/现象 | 用 `【解释】` 包裹，原文不改 |
| 操作指导 | 含步骤编号、操作动词 | 用 `【操作指导】` 包裹，原文不改 |
| 安抚话术 | "不用担心"、"请放心" | 用 `【话术】` 包裹，原文不改 |

**规则**：
- **禁止改写或补全话术**，缺失内容用 `（话术待补充）` 占位
- PPT 中的"提醒："段落作为话术附注，缩进放在对应话术之后
- `undefined` 等明显占位符保留并标注 `（原文如此，疑为品牌名占位）`

---

### Step 4 — 提取诊断判断逻辑

判断表格固定四列（比通用版多一列"出口类型"）：

```markdown
| 条件 | 下一步 | 出口类型 | Mermaid 边验证 |
|------|--------|---------|--------------|
| {用户回答/系统状态} | → **D{xx}** | 继续诊断 | `SOURCE --标签--> TARGET` ✓ |
| {用户接受} | → 结束 | ACC | `SOURCE --接受--> ACC` ✓ |
| {用户不接受} | → **D{xx}** 或派工 | 派工 | `SOURCE --不接受--> DISPATCH` ✓ |
| 其他无法识别的输入 | →【越界退出】 | 越界 | 无对应 Mermaid 边 |
```

**每张判断表格必须有兜底越界行**。

---

### Step 5 — 提取诊断码

BSH 诊断码格式：**12 位数字/字母码 + 英文描述 + 中文描述**。

提取规则：
1. 从 PPT 中识别所有 12 位码（格式如 `111100000000`、`A12200000000`、`B2C200000000`）
2. 同时提取紧邻的英文描述行和中文描述行
3. 一个诊断码可能出现在多个分支出口——**每次出现都标注在对应 D 步骤**
4. 汇总至附录 A，标注每个码的出现位置（D 步骤编号）

特殊情况：
- "创建...DC" / "新建...DC"：表示该诊断码需要新建，在附录 A 中标注 `[待创建]`
- 同一诊断码在多个分支重复出现：在附录 A 中只列一次，标注所有出现位置

---

### Step 6 — 提取派工信息

派工出口包含以下信息，全部提取：

| 字段 | 提取来源 | 示例 |
|------|---------|------|
| 诊断码 | 派工节点关联的 12 位码 | `B2C200000000` |
| 配件建议 | "需要配件" + 具体配件名 | `电磁阀、变频模块` |
| 视频标记 | "视频已有" / "视频：无需" | `视频：无需` |
| 触发条件 | 导致派工的诊断路径摘要 | `不停机 → 封条无问题 → 用户不接受` |

汇总至附录 B。

---

### Step 7 — 提取跨树引用

PPT 中的 "跳转 {故障名}" 提取为跨树引用：

```markdown
【引用】→ 参见 BSH_{系列}_F{nn}_{故障名}.md — D{xx}
```

引用需标注：
- 来源文件和步骤
- 目标文件和入口步骤（如果能确定具体入口）
- 触发条件

汇总至：
- 当前文件的附录 C
- 索引文件的"跨故障树引用关系"表

---

### Step 8 — 定义越界处理协议

每个故障树文件独立定义越界协议。

**触发条件**（至少覆盖）：
1. 用户故障描述无法映射到当前诊断树的任何入口分支
2. 用户回答无法映射到当前 D 步骤的任何条件行
3. 目标跳转节点在 Mermaid 图中无有效连线
4. 用户要求提供本文档未包含的信息（如价格、保修政策）
5. 用户情绪激烈、涉及纠纷、要求升级投诉
6. 用户描述的故障现象属于其他故障树覆盖范围

**退出动作**（按优先级）：
1. 若属于其他故障树 → `【引用】` 跳转
2. 若无法定位 → 转人工客服
3. 若用户要求 → 转人工客服

**覆盖范围边界**：列出所有跨树引用出口，标明为"属于其他故障树，遇到时执行引用跳转"。

---

### Step 9 — 生成 Mermaid 诊断树

为每棵故障树生成 Mermaid 源码：

**Mermaid 规范**：
- 使用 `flowchart TD`（顶到底方向，匹配树形诊断逻辑）
- 诊断问题节点用菱形 `{...}`
- 话术/解释节点用矩形 `[...]`
- 派工出口用圆角矩形 `([...])`
- ACC 出口用圆角矩形 `([...])`
- 跨树引用用双圆角 `((...))` 或注释节点
- 边标签为用户回答或条件
- 节点 ID 规则：`{故障缩写}_{序号}`，如 `NP_01`（No Power 第 1 步）

**节点 ID 前缀推导规则**：

节点 ID 前缀从故障名称的英文翻译中提取，2–3 个大写字母，要求在同一产品的所有故障树中唯一。

推导方法：
1. 将故障关键词翻译为英文短语
2. 取首字母缩写（2–3 个字母），确保与同产品其他故障树不冲突
3. 若缩写冲突，取第二个单词的前两位字母区分
4. 前缀一旦确定，记录在索引文件的"文件清单"表中，全局可查

**推导示例**（仅为说明规则，不限于此）：

| 故障关键词 | 英文翻译 | 前缀 | 节点 ID 示例 |
|-----------|---------|------|-------------|
| 不通电 | No Power | `NP` | `NP_01`, `NP_02` |
| 不制冷 | No Cooling | `NC` | `NC_01`, `NC_02` |
| 噪音 | Noise | `NO` | `NO_01`, `NO_02` |
| 漏水 | Water Leak | `WL` | `WL_01`, `WL_02` |
| 不脱水 | No Spin | `NS` | `NS_01`, `NS_02` |
| 门打不开 | Door Lock | `DL` | `DL_01`, `DL_02` |

```markdown
| 诊断步骤 | Mermaid 节点 | 步骤类型 | 预期下一节点 |
|---------|-------------|---------|------------|
| D01 | `{前缀}_01` | 判断 | `{前缀}_02` / `{前缀}_03` |
| D02 | `{前缀}_02` | 话术 | `{前缀}_04` |
...
```

### Step 11 — 生成附录 C（ASCII 诊断路径图）

用 ASCII 表示主干诊断路径，分支用缩进和树形符号表达：

```
D01 用户主诉确认
 ├─ 情况A → D02 话术引导
 │   ├─ 用户接受 → ACC
 │   └─ 用户不接受 → 【派工】DC: XXXXXX
 ├─ 情况B → D03 进一步诊断
 │   ├─ 子情况B1 → D04
 │   └─ 子情况B2 → 【引用】→ F{nn}
 └─ 其他 → 【越界退出】
```

## 质量检查清单

生成完成后逐项核对：

### 索引文件检查

- [ ] 文件清单表覆盖所有故障树，编号连续无遗漏
- [ ] 一级分流表每个故障树至少 3 个关键词
- [ ] 跨树引用关系表双向完整（A 引用 B → B 被引用于 A）
- [ ] 产品信息与 PPT 封面一致

### 独立故障树文件检查

**结构完整性**
- [ ] 文档包含固定五节（使用说明 / 导航树 / 越界协议 / 诊断入口 / 诊断步骤）和三附录
- [ ] Mermaid 源码完整内嵌，树形结构正确
- [ ] 诊断步骤 ↔ 节点速查表覆盖所有步骤

**Mermaid 导航锚**
- [ ] 每个诊断步骤标注 `[节点：XXX → YYY]`
- [ ] 每张判断表格有"Mermaid 边验证"列
- [ ] 每张判断表格有"其他/无法识别"兜底越界行

**越界协议**
- [ ] 越界协议独立成节，放在诊断步骤之前
- [ ] 触发条件不少于 6 条（含"属于其他故障树"）
- [ ] 严禁行为列表已列出
- [ ] 覆盖范围边界（含跨树引用出口）已列出

**话术和诊断逻辑**
- [ ] 每个判断的所有 Mermaid 出边均有对应条件行
- [ ] 所有派工出口均标注诊断码、配件、视频
- [ ] 话术原文未被改写（缺失内容用占位符标注）
- [ ] 附录 A 诊断码与正文 `【诊断码】` 标记一一对应
- [ ] 附录 B 派工信息与正文 `【派工】` 标记一一对应
- [ ] 附录 C 跨树引用与正文 `【引用】` 标记一一对应

**PPT 输入专项**
- [ ] Step 0 已执行，提取路径已明确
- [ ] 被过滤的非流程页已列出页码
- [ ] 故障树边界识别明确，或已向用户确认
- [ ] 所有 "跳转" 指示均已转化为跨树引用
- [ ] "创建...DC" / "新建...DC" 指令已在附录 A 标注 `[待创建]`
- [ ] `undefined` 等占位符已保留并标注

## 执行顺序总结

```
Step 0: PPT 预处理
  ├─ 0-1: 确定提取路径
  ├─ 0-2: 过滤非流程页
  ├─ 0-3: 故障树边界识别 → 输出故障树清单
  └─ 0-4: 按故障树提取节点与边

Step 1: 生成索引文件（先产出索引，再逐棵写故障树）

Step 2–8: 对每棵故障树重复执行
  ├─ Step 2: 划分诊断步骤
  ├─ Step 3: 提取话术与解释
  ├─ Step 4: 提取诊断判断逻辑
  ├─ Step 5: 提取诊断码
  ├─ Step 6: 提取派工信息
  ├─ Step 7: 提取跨树引用
  └─ Step 8: 定义越界处理协议

Step 9: 生成 Mermaid 诊断树
Step 10: 生成速查表
Step 11: 生成 ASCII 路径图

最终: 按质量检查清单逐项核对
```
